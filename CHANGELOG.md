## [Unreleased]

### Added

- `jhon executions forget <project> [--root <project>]` drops a uv-run pytest project's pytest-testmon record, and the worktree's own from before the shared one, so the next affected run builds it again, every test once (T255, odd/tasks/t255.md L1725). The whole record, not only its failed marks: a test that failed because a service was down recorded only the code it ran before failing, and trusting it as passing would select less.

Such a refusal now ends `its target cannot be resolved; assign the scratch folder first, on its own: d=$(mktemp -d); cd <dir> && …; rm -rf "$d"`, and that form is allowed. `rm -rf "$d"/*`, the folder's entries, stays refused, as every other spelling but the whole folder does: a failed mktemp leaves `d` empty, and `"$d"/*` is then `/*`. `mktemp -d --tmpdir` with no `=` is read as GNU reads it, the temporary root (it took the next word as the folder). A reassigned variable, one assigned from anything else or used before the assignment, `$d/..`, `${d:-/}`, another variable and `rm -rf $d $HOME` are still refused. Holes found on the way are closed: the name `_` was read as a scratch folder, but the shell sets `$_` to the last argument of the command before, so `_=$(mktemp -d); echo ~; rm -rf $_`, which removes the home folder, was allowed; `_` is never a scratch folder now, and zsh's `pipestatus` (it reads as the last exit status) and `histchars` (it keeps three characters) are never assignable on a line the rule reads. zsh's builtins that assign a variable or change the shell's state (`print`, `strftime`, `zparseopts`, `vared`, `getln`, `sysread`, `zmodload`, `zstyle` and the like) are no longer read as external programs, and a word that is the variable's name glued to an option cluster (`-vd`, `-nvd`, `-sd`) or with a subscript counts as an assignment of it: `d=$(mktemp -d) && print -vd ~ && rm -rf $d`, which removes the home folder in zsh, was allowed and is refused now. zsh also runs code in the shell itself through a glob qualifier (`*(e:…:)`, `*(+f)`), `repeat`, `-` and `private`, so a line holding an extended glob or one of those is not read either: `x=d; d=$(mktemp -d) && repeat 1 typeset -g $x=$HOME && rm -rf $d` and its siblings, allowed before, are refused. The safe-form sentence is given only for a folder made by `mktemp -d` that the rule reads.
- `jhon audit` no longer counts a relaunch because a sub-agent's result says "refused:" in ordinary text (T224 S2), such as "Any other entry is still refused: the new tests cover …". A result says the agent stopped short only with its turn cap or one of Jhon's own refusal lines, by the exact prefix Jhon prints them with, quoted or not, wrapped in markdown or brackets too (`**…**`, `_…_`, `__…__`, `(…)`, `[…]`) but never inside another word (`my-safety-guard: `): a guard's (`safety-guard: `, `scope-guard: `, `route-guard: `, `vcs-guard: `, `secrets-guard: `, `framework-guard: `, `inspect-guard: `), the sandbox's `sandbox: …; the call is refused` and `the sandbox refused a write to …`. The other guards' refusal lines, which never said "refused:", now count too.
- Sandbox: the agent is told how the owner's deploy tools run (T217). With `sandbox.mode` on, a program in `sandbox.deploy_tools` runs outside the sandbox only alone on its line, and nothing said so: an agent put `aws` on a line with `export`, a pipe and other commands, got `Unable to locate credentials` and concluded the sandbox had to be turned off. A work line that holds a listed tool now ends, whether it failed or not (not when a signal killed it), with one note on stderr, after the read-only and git/gh notes: `aws runs outside the sandbox (sandbox.deploy_tools) only on a line of its own, called by its name, with no pipes, ;, $(…), ~, $VAR or VAR=value in front, or other commands: run it alone, as in aws <arguments>, and pass settings as options (--region, --profile), not variables` (`aws and cdk run …` for two); the exit code is unchanged, and a listed tool alone on its line, a line with none, and a tool not listed get no note. The always-on lean text of both runtimes says, before anything runs, that git over SSH, `gh` and the deploy tools run outside the sandbox only alone on their line (a leading `cd <absolute project dir> &&` allowed), and that a failure inside the sandbox is fixed by running the program alone, not by turning the sandbox off.
- Sandbox: Jhon's own Engram writes made inside the sandbox reach Engram (T222). `jhon executions verify`, `jhon archive` and `jhon context` run `engram save` and `engram search` from sandboxed bash, where Engram's folder (~/.engram) is read-only, so every change-state save failed (`engram: acquire instance identity lock: open migration lock file …/.engram/.instance-id.lock: … read-only file system`). Engram's folder stays read-only (a writable one lets a sandboxed command steer what Engram does outside the sandbox); instead, inside the sandbox, or where Engram fails on a read-only file system, the state record is queued in `<git common dir>/jhon/engram-queue/`, one file per record, with `jhon: the state of <change> was queued for Engram; Jhon saves it outside the sandbox`. Every jhon command run outside the sandbox, the agents' hooks included (a hook flushes its payload folder's queue), first saves each queued record to Engram from the repository's main worktree and removes it, so the state arrives by the agent's next tool call. Only a well-formed state record of Jhon's own is saved (`ldd state: <change>` under topic `ldd-state/<change>`, the state's content, naming the main worktree, at most 64 KiB); anything else, a link or a folder included, is moved to `engram-queue/refused/` (the newest 100 kept), named on stderr quoted and never saved, and a write left half-done for a minute is removed. No link is followed anywhere on the way: the git common dir is opened with `openat2` and `RESOLVE_NO_SYMLINKS`, so no component of its path may be a link, then `jhon/`, the queue and `refused/` each relative to the one before with `O_NOFOLLOW`, every read, move and removal relative to them, and Engram runs in the main worktree entered the same way; on a kernel without `openat2` (before Linux 5.6) the queue fails closed, said once on stderr and by `jhon doctor` with the fix. One flush takes at most 5 s, listing and removals included. A record Engram does not take waits, said once on stderr. `jhon doctor` says why Engram did not take the records, how many wait, how many entries were refused, and a queue it cannot read, with the fix, every path quoted; a queue that cannot be written says `fix: run jhon doctor`. A search that fails inside the sandbox on a read-only file system (anywhere in engram's stderr) says the sandbox keeps Engram's folder read-only, and `decisions_note` says to search with the MCP memory tool (`mem_search`). Accepted residuals: a sandboxed command can queue a well-formed record with false content for any change name, only ever saved under `ldd-state/<change>`; and the Engram project a record lands in is the one Engram derives from the main worktree's files (git remote, `.engram/config.json`), which a sandboxed command can write, as for the agents' own saves.

- route-guard holds every move of the default branch to the delivery check (T219): a command that moves `main`, `master` or the branch origin/HEAD names to another commit runs only when a ready `jhon deliver check <change> --action merge` on record covers that commit (the same commit, or one whose tree differs only in the change's record; only records in the worktrees and the git common dir count, never one a commit carries). The gate limits only the agent, never the owner (S9): git's hook judges a git that carries `JHON_AGENT=1`, which `jhon sandbox run` (both profiles), pi's shell (the agent's bash, its jobs and monitors, sub-agents included, with the sandbox on or off) and Claude Code's pre-tool with the sandbox off (`export JHON_AGENT=1` before the command, as an updatedInput with no permission decision, so Claude Code's own prompts are unchanged) give the agent's commands; the owner's terminal and the owner's `!` commands carry none and are never refused, and the hook's shell line exits at once for them without starting jhon. route-guard refuses an agent line that changes the marker or git's configuration through the environment as the line runs it (an assignment, export, declare, typeset, readonly, local, unset, read, `printf -v`, an exported function, `exec -c`, env by any path with `-i`, `-`, any abbreviation of `--ignore-environment`, `-u`/`--unset` or `-S`), with its words read as the shell gives them (quotes and backslashes removed, brace lists expanded, `${!PREFIX@}` naming every variable with that prefix), and never a line that only reads or searches for the names (`printenv JHON_AGENT`, `echo $JHON_AGENT`, `rg GIT_CONFIG_COUNT`). The hook's shell line uses keywords and special builtins only and takes away any function named after the builtins it runs, so an exported function cannot change it. The gate limits the agent through the marker the agent's own commands carry: an agent that strips its own environment by means a line cannot show (a script, a program it starts) is outside what a line or a hook can stop, as is `eval` of a string built at run time; `jhon audit` reports a move of the default branch only when the agent's line itself writes it, so such a move is not reported. A commit, a cherry-pick or an `am` the agent makes on the default branch is refused the same way: work on the change's branch. The hook no longer decides from the work tree's files or HOME (its own entry in the repository's configuration marks the repository), allows creating the default branch only in a repository with no commit at all, and runs its own git reads with the system's git, whatever PATH or GIT_EXEC_PATH a line sets; route-guard also refuses an alias value with `-c` of a hook key, core.hooksPath or an include (quotes removed), and a line that sets or clears a `GIT_CONFIG_*` variable (`printf -v`, `read`, `declare`). Other hooks, `.git/hooks` and `core.hooksPath` keep working; on an unsandboxed git line (sandbox on) every hook stays off but the merge gate, with Jhon's own values. route-guard refuses a command that removes or turns off the gate (`git config` of `hook.jhon-*`, `hook.reference-transaction.*` or an include, `-c` with one, a line that sets a `GIT_CONFIG_*` variable). `jhon doctor` warns when a repository under LDD has no gate. Each git command that updates a ref pays git's cost of starting the hook's shell for each transaction state, the owner's too (about 25-40 ms on a commit or a checkout where /bin/sh is bash); jhon itself starts only for the agent's update of the default branch. With no `branch.main.remote`, origin counts as main's remote for `pull` and `fetch` too. Accepted residual, which `jhon audit` reports only when the line itself writes the move (a merge before a ready check): a script file that turns the hook off for its own git commands, `git branch -M|-C` onto the default branch from a script (git runs no reference-transaction hook for a rename or a copy; route-guard refuses it on the line), direct writes to `.git/refs`, `packed-refs` or `.git/config` from inside the sandbox, a forged upstream written in the same transaction or a remote-tracking ref forged in one step and merged in another, and a delivery record written by hand.

## [0.4.0] - 2026-11-23

Jhon orchestrates in any project and runtime: in pi it can delegate to sub-agents from a session's first request, on every provider, and in pi and Claude Code a session that starts lean switches to the full context as soon as its change is not small. It answers in the owner's language, and each sub-agent carries a label that says what it does. In the sandbox, the owner's deploy tools run outside it (`sandbox.deploy_tools`), and an `XDG_CONFIG_HOME`, `XDG_STATE_HOME` or `JHON_SETTINGS` in a writable folder can no longer turn it off. Three issues the certification found were fixed before the tag: a change that gets its folder mid-change keeps its RED (T208), the bench waits for background sub-agents (T209), and the safety guard no longer takes a module a script imports for a file it deletes (T210). The shell is built against pi 1.5.2 and type-checks with TypeScript 7.0.2. How this release was certified, what failed and why it shipped anyway: [the v0.4.0 release notes](https://github.com/jachavarro2004/jhon-agent/releases/tag/v0.4.0).
