# Changelog

All notable changes to Jhon are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Changed

- Sandbox: Jhon's source checkout (the one `jhon sync` installs from, or the checkout run directly) is read-only in the sandbox of every other project, a linked worktree of it included, which still commits through the checkout's git folder; with the checkout itself as the project nothing changes. With `sandbox.mode = "off"` on Linux `jhon doctor` warns instead of ok: the guards leave a shell command's writes outside the project to the sandbox, so off they run unguarded (a redirect, `dd`, a recursive `chmod`, Jhon's installed files and source) (T128f slice 7, L1367, L1371).
- safety-guard: reading a credentials file is no longer judged in a shell command or interpreter code, in the project or outside it (the Bash allow-list, extension-glob walk and code reading behind it are deleted), and a write whose target cannot be resolved no longer asks; the always-on prose (orchestrator.md, lean.md) now says no agent reads a credentials file even when the owner asks. Still refused: a shell write or delete of a credentials file (rm, truncate, dd of=, a redirect, tee, cp/mv/install/ln onto it, sed -i, curl or wget -o; `go build -o` is an accepted residual), every destructive rule, and the file tools' secrets-guard. guarddiff against v0.3.7: 169 more safety-guard verdicts change, listed in tools/guarddiff/allow.tsv as read (98, four of them refuse to ask: a preload still asks), non-destructive-write-ask (68) and credential-write (3: two bare `dd of=` v0.3.7 missed now refused, one `go build -o` allowed); 38 slice-5 rows went back to v0.3.7's refusal and left the list (T128f slice 6, L1366, L1368, L1369).
- safety-guard: a shell write outside the project no longer asks (outside-write), and dd or a recursive chmod/chown there is no longer refused; a credentials file the shell names outside the project (another repository, the home's credentials, a scratch root) is no longer refused. The sandbox keeps them read-only or hidden (on Linux; macOS and Windows run unsandboxed, D3). Still refused or asked as before: a credentials file in the project or one the guard cannot place (`cat .env`, L1354; reads dropped in slice 6), a write into `.git`, the grants or a Claude Code settings file, a write whose target cannot be resolved (dropped in slice 6), a deletion outside the project, and Edit or Write outside the project (vcs-guard). guarddiff against v0.3.7: 654 safety-guard verdicts turn ask or refuse to allow, listed in tools/guarddiff/allow.tsv as class S outside-write (547) and outside-credential (107) (T128f slice 5, L1362).
- framework-guard: on Bash it keeps only the T81 rule (interpreter code, or a script run from a file, naming a framework path is refused: Jhon's own code is never run by hand). Its Bash write checks (redirects, writers and wrappers, find -delete, shell and interpreter code writing, an unreadable line naming a framework path) and its refusal of git on a framework path are deleted: the sandbox keeps the framework and the home read-only (on Linux; macOS and Windows run unsandboxed, D3). Edit and Write of a framework path stay refused. guarddiff against v0.3.7: 241 framework-guard verdicts turn refuse to allow, all listed in tools/guarddiff/allow.tsv as class S framework-bash (T128f slice 4, L1360).
- `tools/guarddiff`: the guards' verdict differential (T128f): every line of test/guards/corpus (the corpus, the T59 matrix, route-guard and scope-guard rows, a seeded 3,600-line fuzz set) through two jhon binaries' guards; a changed verdict not on tools/guarddiff/allow.tsv fails, and the pre-push hook runs it against the last release when the push changes what judges or feeds the guards. v0.3.7 against this head: no verdict changed.
- Sandbox: `sandbox.mode` is on by default on Linux, so pi and Claude Code run each command of the model in the sandbox unless the settings say `off`; where the sandbox cannot run (no bubblewrap, user namespaces off) every command is refused with the fix and `jhon doctor` reports a problem. On macOS and Windows the default reads as off: commands run unsandboxed and `jhon doctor` warns; an explicit `on` there still refuses every command. `jhon sandbox status --json` adds `mode_source` (`default` or `settings`) (T128f, L1352).
- Sandbox: with `sandbox.mode = "on"`, a line whose every program is docker or docker-compose (any command: `ps`, `build`, `run`, `compose up`, `push`) runs outside the sandbox in pi and Claude Code with the owner's environment, so the rootless context and `DOCKER_HOST` work; Docker is the owner's deployment tool, so its volume mounts are not judged. `docker login`, `docker logout` and `docker context create|use|rm|update|import|export` keep the work profile, as does a mixed line (`docker ps && npm test`), a redirect to a file, an unreadable line and a docker or docker-compose a sandboxed command could have written (T128h, L1331).
- Sandbox: a single-quoted word, and a double-quoted one with no `$` or backtick, is read as literal text, so `docker ps -a --format '{{.Names}}'`, `docker ps --filter 'name=a*'` and the same quoting on git and gh lines no longer force the work profile; `docker --version` and `docker -v` run unsandboxed. A `$`, a backtick, a parameter, a substitution and an unquoted glob or brace still give work (`docker ps --filter name=a*` included, as `git fetch * origin`) (T128h2, L1338).
- Sandbox: with `sandbox.mode = "on"`, a line of git network commands (fetch, pull, push, ls-remote, clone, remote update, listed options only, working inside the project, a clone included) or gh (a listed subcommand, not auth, extension, alias or config, nothing downloaded) runs outside the sandbox in pi and Claude Code, still judged by the guards (`jhon sandbox profile [--project <folder>] -- <line>`); every other line, one that redirects to a file, and one Jhon cannot read keep the work profile. That git runs with `core.hooksPath=/dev/null`, `core.sshCommand=ssh`, `core.fsmonitor=false`, the repository's credential helpers reset (the owner's global and system ones kept), the ext, fd and file transports off, no submodule recursion and `hook.<event>.enabled=false` for every hook event (hooks named in the configuration, git 2.54+, included), after the owner's own `GIT_CONFIG_COUNT` entries; `url.*.insteadOf` and `include.*` in the repository's configuration remain an accepted residual risk. In the work profile uv's tools go to `$XDG_CACHE_HOME/jhon/sandbox/uv-tools` (`UV_TOOL_DIR`, `UV_TOOL_BIN_DIR`, unless set), and `~/.local/share/uv` stays read-only (L1305, L1306). A wrapped command that fails on a read-only path ends with `the sandbox refused a write to <path>; that is a stop: tell the owner the path (jhon settings sandbox.allow_write), never write it elsewhere`, and every run records a `jhon.sandbox` telemetry event (profile, exit code) (T128g).

### Fixed

- Sandbox docs: `--die-with-parent` ends bubblewrap and its command, not a child the command detached (`setsid`, `nohup`): with no PID namespace that child outlives the sandbox, an accepted residual risk (T128g, L1262).

## [0.3.7] - 2026-11-18

### Added

- A lean session context: with no active change, or a small one, a session starts with `prose/lean.md` alone (identity, the limits, the small change's two runs, what to read when; about 2.3 KB on each runtime). The full context, today's orchestrator and always-on layer, is installed as `~/.local/share/jhon/current/prose/full-<runtime>.md`. It loads when `jhon status` prints `not small: read <full file> before the next edit`, when a session starts on a change that is not small (Claude Code SessionStart, pi's session-brief `context`), with one persisted `jhon-full` message on pi's not-small status or first `subagent` call, and with a PostToolUse pointer in Claude Code. Sub-agents keep the full layer (T146h).
- On a lean pi session, Jhon's own tools (`jhon_review`, `subagent*`, `m365_read`, background tasks, Engram) and the skills list wait behind `tools_more` until the full context loads; `todo`, `ask_user`, `inspect` and codegraph stay (T146h).
- bench: `--pi-models <file>` on `prepare` and `run` gives pi-jhon and pi-clean the same provider (a pi models file copied into the bench HOME and each pi-clean agent dir; never printed); the dry run names each condition's models (T146).

### Changed

- bench: `value` gates a small task's cost on turns, Jhon's median at most the clean median + 6 (the LDD minimum: branch, test-first, RED run, GREEN run, commit, deliver check); its weighted tokens, cost usd and active time are shown as INFO, never failed. Large tasks and the quality gates are unchanged (T146i, L1285).
- A small change names the bare `jhon executions run` everywhere: status's next command and RED/GREEN note (two runs, nothing between), the pending-branch note, and pi's LDD reminder. `jhon executions --help` and `jhon executions run --help` open with the two-line common case (T146h).
- A lean pi session (no change, or a small one) gets no todo start rule or start nudge, and the todo tool's guideline says a small change keeps no list (T146h).
- Claude Code's `jhon-orchestrator` agent definition is the lean text; its full context is the install's `full-claude-code.md` (T146h).
- `jhon status` and a bare `jhon executions run` on the default branch with no change name the commands a small change starts with, `git switch -c <name>` then `jhon executions run`, instead of `start-change` (no command); one that is not small keeps "start one (tasks.md)" (T146g).
- `jhon deliver check` before the commit, when the last passing run tested the working tree as it is, says "commit it, then `jhon deliver check <change>`, with no re-run"; every delivery order reads: a passing run, commit the tree it tested, then `jhon deliver check` (T146g).
- A small change keeps no tasks.md, archive, light verify or todo list: status asks no light verify of it, the route guard opens its PR without one, and the orchestrator, the light-verify rule, the session's route text and pi's todo text say so in the same words (T146g).

### Fixed

- bench: GLM weights from Z.ai's current GLM-5.3 prices; GLM and DeepSeek models on NaN weighed by NaN's own credits (T146).
- Rendered prompts and agents name the install by its real path under the rendered HOME, never `~/.local/share/jhon/current`: a model expanded the `~` from the user name in its working directory, and two bench runs read the owner's own install (T146g).

## [0.3.6] - 2026-11-17

### Added

- `jhon executions run` with no change name runs the change the branch selects and names it first; `jhon status` prints the exact next command (T146).
- bench: `value` gates each cell by task size (small <= 1.1x, large <= 1.25x with strictly better quality); Jhon plain runs start on a repo already set up for LDD, with the one-time set-up measured apart; tokens weighted per provider (Claude, GLM) plus cost_usd, quota apart; median (min-max); default repeats 5 small, 3 large (T146).

### Changed

- The RED-before-GREEN hints (jhon status, the route guard's PR refusal, a light verify's refusal) and the LDD prose follow the inner loop: the slice base for the RED record and the slice's close, a unit's run (--affected) between (T145b).
- A small change (no folder, one component, under the advisory size, not high risk) keeps no tasks.md, memory, session summary or todo list; `jhon deliver check` accepts the GREEN run whose recorded working tree is the commit, with no re-run (T146).
- The fixed context drops ~31% on both runtimes (Claude Code 32879 -> 22864, pi 32661 -> 22709 bytes): delivery, delegation, remote/destructive-operation and TDD-witness rules move to contracts read on demand behind precise pointers, each pinned by validation (T146).

### Fixed

- pi's prompt names Engram and CodeGraph tools as pi registers them, and its own background tools (T146).
- bench: the jhon condition no longer loads the owner's CLAUDE.md or auto-memory (T146).
- The delivery rules the fixed-context cut dropped are back (the high tier's verify report or Judgment Day record, the RED/GREEN record, hand-run suites get a note), the ambient-credential and owner-act rules are back in the always-on remote-auth contract, and contract pointers name the install's real path; validation reports an on-demand problem against the prose file at fault (T146c).
- `jhon deliver check` no longer takes a run whose working tree changed while it ran as the tested tree (the run records its working tree again when it ends; a difference marks it dirty), and the committed-tree evidence applies only to a run that passed and finished (T146d).
- `jhon deliver check` refuses a test record written by 0.3.1-0.3.5 (no `after_working_tree`) as evidence for the committed tree and says to run the tests again; the delivery-evidence note appears only on a run it accepts, never on a refused unit run (T146e).
- A run no longer reuses passes from, measures a unit's run from, or closes a slice on a test record written by jhon 0.3.1-0.3.5 (no `after_working_tree`): such a record cannot show its working tree held until the run ended. After updating, a slice or delivery recorded by an older jhon needs one re-run, `jhon executions run <change> --affected <base>` (T146f).
- Tests: the shell suite and the git hooks' Go tests no longer read the machine owner's Jhon settings or state (T147).

## [0.3.3] - 2026-11-17

### Added

### Changed

- Each integration (Engram, CodeGraph, Context7, the Microsoft 365 connector) is described by a manifest, `integrations/<name>/manifest.yaml` (schema `jhon.integration/v1`): its MCP servers per runtime, the capabilities it grants, its setting, doctor pin and setup text. The engine reads them through `engine/internal/integrations` instead of naming them, and `jhon validate` refuses a malformed manifest naming the file and the field. Rendered output, setup and dashboard are unchanged (T58a).

### Fixed

- The `validate` workflow's failures on GitHub's runners are fixed: text files check out with LF on every platform (`.gitattributes`; the CRLF fixtures stay CRLF), the Windows-portable packages' tests expect Windows paths where Windows shows them, the sandbox pass-through test uses a program of its own instead of the system `printf --help`, the cross-run executions test proves the overlap with a barrier instead of a timed race, and the Linux job is pinned to `ubuntu-24.04` (L1142).

- One context notice, at `shell.behaviour.fresh_session_at`; the 5h window shows from 70%. Tool icons are geometric by default (`shell.appearance.icons = "emoji"` brings the emoji back).
- The dashboard reads in the shared states table and rose ink's roles; a session's page shows what the session did, and a change's state lives on the Changes pages. Its API answers only a request to 127.0.0.1, localhost or [::1] on its own port and refuses another site's Origin (403); its memory routes refuse a link or a directory outside `~/.claude/projects`.
- The repository's pre-commit hook checks only what a commit touches; a pre-push hook runs the whole suite when a push updates `main`.

## [0.1.0] - 2026-11-07

The first public release: Linux (amd64 and arm64), and Windows through WSL 2.

### Known issues

- `install.ps1` (Windows through WSL 2) has not been run on a real Windows machine yet; only its Linux side, `install.sh`, is tested end to end. If it fails for you, please open an issue at https://github.com/jachavarro2004/jhon/issues with the window's output.

### Added

- Install in one line from GitHub raw: `install.sh` (`curl -fsSL https://raw.githubusercontent.com/jachavarro2004/jhon/main/install.sh | sh`) downloads the latest release (or `JHON_VERSION`), checks its sha256 and, when `cosign` is installed, its keyless signature, installs it and opens `jhon setup`; any failed check installs nothing.
- Windows through WSL 2: `install.ps1` checks WSL, the distro, WSL 2 and curl, then runs `install.sh` inside the distro. Native Windows comes in v0.2.
- Signed releases on [jachavarro2004/jhon](https://github.com/jachavarro2004/jhon): per arch, `jhon-X.Y.Z-linux-<arch>.tar.gz`, its `.sha256` and a cosign keyless `.sigstore.json` bundle, built and signed by the public release workflow. Pre-releases are tagged `vX.Y.Z-rc.N` and never offered as the latest.
- Static binaries: `jhon` is built without cgo and `herdr-jhon` against musl, so neither needs a particular glibc (WSL's default Ubuntu 22.04 works).
- The core LDD engine in one Go binary, `jhon`: validation and projection of the contracts, status, the launch context, compose, archive, judgment, and the transcript auditor.
- The guards on every tool call (safety, write, framework, scope, and inspect, among others), with time-boxed `jhon grant` authorizations for what they ask about.
- Two runtimes over the same core: Claude Code (`jhon start`, its plugin and `/jhon-ldd`) and pi (`jhon start pi`, with `jhon-shell`); each can be turned off in settings. With no setting, a runtime is on only where it is found (`~/.claude` or `claude` on PATH; `~/.pi` or `pi` on PATH), so a fresh home gets only the core; `jhon setup` shows what it found and lets you choose.
- Versioned owner settings (`schema = 1`, `.config/jhon/settings.toml`) read and written through `jhon settings`.
- Opt-in integrations, off by default: herdr, the dashboard, telemetry, and following a desktop palette.
- Per-project permission modes (`jhon mode`: normal, yolo, super-yolo) and the owner's model profiles (`jhon profile`).
- `jhon version`: the version, commit and date stamped into every build.
- `jhon <command> --help` prints the command's own help for setup, start, update, doctor, status, version, settings and profile; `jhon --help` lists the maintainer's commands (sync, publish, release pack, test, validate, check) apart, under their own heading.
- An installed release works without the source checkout: `jhon doctor` checks the installed release, nothing rendered names a source path, and `jhon sync`, `jhon release pack` and `jhon test` (the maintainer's) say they need the checkout and point to `jhon update`.
- `jhon release pack` and `jhon release install`: the release artifact (`jhon-<version>-linux-<arch>.tar.gz` with its `.sha256`) built from a checkout, and installed from it with no checkout and no toolchain; `jhon sync` composes both.
- `jhon setup`: the setup wizard with its progress rail (Bubble Tea and Lip Gloss, in rose ink): runtimes, opt-in integrations, dependency checks with their fixes, then the settings and the install.
- `jhon update`: the latest release, verified (sha256 and its cosign keyless signature, with sigstore-go inside the binary, no external tool) before it is installed; `--check`, `--json`, `--rollback` to the previous release; on a terminal, the setup TUI's update screens.
- While only pre-releases are published, `install.sh` without `JHON_VERSION` says no stable release is published yet and points to the releases page, and `jhon update` (`--check`, `--json` status `no-release`, the update screen) says so and exits 0, changing nothing.
- herdr, opt-in: when setup turns it on, the release's `herdr-jhon` is installed with its `jhon.sidebar` plugin, placed and linked; with herdr off nothing of it is installed.
